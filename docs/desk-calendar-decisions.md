# 桌历功能决策记录（2026-09-05 定稿）

本文记录桌面日历已经确认的产品边界。正式实现位于 `deskCalendarHost.ts`、`deskCalendarStateStore.ts`、`calendarDataService.ts`、`scheduleDomain.ts` 与主日历、桌历两个渲染入口；逐项验收见 [桌历与重复事件 spec](specs/desk-calendar-and-recurrence.md)。

## 一、窗口行为

- **运行形态**：桌历是 Schedule 模块的一项 Electron `BrowserWindow` 能力，与 CampusOS 共用进程生命周期；旧 DeskToDo/PyQt 只作对照，不是运行路径。
- **贴底层级（交互回归后更正）**：始终在桌面之上、普通应用之下，不提供置顶模式。WorkerW 壁纸层挂载已实测被图标层截获鼠标，故按原先允许的降级边界改为可交互的独立顶层窗口，只调整自身 z-order 到桌面输入宿主上方；不再声称同时位于图标下方且可直接鼠标交互。旧置顶设置自动清理，其余偏好保留。
- **布局**：月、周、日三视图；格子随窗口均分拉伸，窗口不出现整体滚动条，单日事件过多时只在格内滚动。
- **位置记忆**：按显示器组合签名保存位置和尺寸；恢复位置在任何显示器上都没有足够可操作区域时回退主屏默认位置，不能因只剩几像素而继续沿用。
- **调整**：默认允许拖动和缩放；图钉锁定位置与大小；不做贴边吸附。

## 二、事件交互与字段权限

- 双击空白日期格新增本地事件，名称、开始、结束必填，地点、备注和提醒可选；不提供无日期待办。
- 单击事件显示信息卡；双击任何事件进入编辑。
- 本地事件可编辑全部字段。课程、考试、上游作业等抓取事件的名称、时间、地点、类型和来源保持只读，只允许保存本机个人备注和提醒；个性化覆盖不改写正式抓取数据。
- 事件颜色只表达课程、任务、截止、考试、日程等类型，不提供颜色优先级。
- 已完成事件灰显并显示删除线。格子不提供右键菜单。

## 三、重复规则与实例编辑

- **规则**：不重复、每 N 天、每 N 周并选择星期、每 N 月、每 N 年。旧数据中的“工作日”规则继续兼容读取，但不再作为新建选项；不做任意日期集合式规则。
- **结束条件**：永不、指定日期、指定次数。指定日期包含当天；指定次数包含第一次。
- **月末语义**：每月或每年落在目标月不存在的日期时，使用该月最后一天。
- **编辑范围**：重复实例可选“仅本次”“本次及未来”“整个系列”。仅本次写实例覆盖；本次及未来把旧系列在该实例前截断并创建同组新段；整个系列更新系列根规则。
- **独立状态**：每次 occurrence 使用稳定序号标识，完成、恢复、删除、个性化时间与提醒互相独立；删除单次不会删除整个系列。
- **修复后的范围契约**：序号跨分段连续；整个系列从最早根起点应用时间差，本次及未来替换已有后续分段。软删除保留底层完成状态，恢复不会抹掉历史；指定结束日期无效时必须拒绝保存并保留草稿。

## 四、统一日历数据

数据优先级依次为：

1. 用户本地维护的放假/补班覆盖；
2. 浙江大学官方 `academic.calendar-config@1` 的开课日和学季边界生成校历周次；
3. 内置农历、节日、节气与宜忌负责展示；
4. 某日没有校历周次时，回退周一开始的自然周。

主日历和桌历消费同一份主进程校历服务，不能各自维护冲突的周次算法。校历人工覆盖、桌历设置、显示器位置、可见状态和上游事件个性化全部存入 SQLite；旧 JSON 只允许一次性导入。

## 五、设置与生命周期

- 托盘“日历设置”和桌历右上角齿轮打开同一设置面板。
- 显示项包括节假日、节日、农历、24 节气、宜忌黄历和周数；外观包括毛玻璃、背景色、透明度和五类文字/边框颜色；主题可独立选择浅色、深色或高对比。
- 桌历“随 CampusOS 开机恢复”从属于 CampusOS 全局开机自启。全局关闭时桌历开关强制关闭且不可开启；全局开启后用户仍需单独选择是否恢复桌历。
- 日程模块停用或 CampusOS 退出时关闭桌历；桌历不创建独立系统登录项。

## 六、明确排除

- 无日期待办、颜色优先级、任意日期集合式重复、贴边吸附、格子右键、多语言、微信/公众号推送、账号/VIP、在线壁纸或组件市场。
- 桌历不重复提供主界面已有的 iCal、Markdown、图片导入导出能力。
- 桌历不通过拖拽事件条改时间；时间修改进入编辑表单。主日历已有拖动入口仅在实际改动时间时保存，点击、双击和取消拖动不能写库。

## 七、自查记录

- **代码入口**：主窗口与桌历均从共享 schedule IPC 加载正式任务与稳定 occurrence；上游个性化通过独立 IPC 写入 SQLite。
- **数据链路**：SQLite migration 12 新增 `desktop_calendar_state`，承载设置、位置、可见状态、人工校历和事件个性化；遗留 JSON 只作一次导入。
- **错误边界**：保持独立顶层窗口，桌面宿主未找到时不改动 Explorer；全局开机自启关闭清除桌历恢复偏好；上游事件编辑不接受正式字段写入；本地无效输入保留草稿并显示错误。
- **用户可见行为**：两个日历入口都提供双击编辑、统一重复规则与编辑范围；桌历设置明确显示开机恢复的从属关系。
- **最终验证**：以 [桌历与重复事件 spec](specs/desk-calendar-and-recurrence.md) 的验证记录为准；历史批次的测试数量和截图不复用。
