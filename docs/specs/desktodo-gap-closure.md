# DeskToDo 差异闭环计划

## 目的

本文件记录 CampusOS 与仓库内 `.tmp/DeskToDo` 对照实现之间的十项桌面效率能力差异。GitHub Gist/日历同步不在范围内：该能力已确认不可用，不作为 CampusOS 的缺口或验收项。

每一项必须同时具备：正式数据/IPC 链路、用户可见交互、持久化边界、针对性测试和自查结果。仅添加按钮、静态占位、mock 成功提示或只读展示不得标记为完成。

## 差异矩阵

| ID | 能力 | 当前基线 | 目标验收 | 状态 |
|---|---|---|---|---|
| DTD-01 | 桌面日历直接完成、编辑、新建任务 | 桌面日历详情页只读，复杂编辑回主窗口 | 在桌面日历完成本地任务、打开真实编辑流程，并可从日期/时间段新建；上游课程、考试、作业仍只读 | 已完成（2026-08-16） |
| DTD-02 | 无日期待办侧栏 | 日程任务以日期/时间为中心 | 可创建、编辑、完成、删除不绑定日期的本地待办；持久化、备份、提醒和搜索使用同一任务链 | 已完成（2026-08-16） |
| DTD-03 | 系统托盘入口 | 托盘生命周期和视图控制已存在 | 托盘可打开/隐藏主窗口、显示/隐藏桌面日历、切换月/周/日、退出；状态与插件停用一致 | 已完成（2026-08-16） |
| DTD-04 | 桌面时钟 | 无独立桌面时钟组件 | 可启用/禁用并在桌面日历中显示运行时本地时间，不写死时间 | 已完成（2026-08-16） |
| DTD-05 | 天气组件 | 无天气连接器或桌面天气组件 | 使用正式天气 provider；可配置地点、刷新、错误状态和缓存，不在视图层伪造天气 | 待实现 |
| DTD-06 | 通用倒计时 | 有考试倒计时，缺通用用户目标 | 可创建多个带标题和目标日期时间的倒计时，目标来自用户设置并持久化 | 待实现 |
| DTD-07 | 通用进度条 | 无用户自定义时间进度条 | 可创建多个起止日期进度条，百分比由运行时当前日期计算，处理未开始/已结束边界 | 待实现 |
| DTD-08 | 组件启用、排序、配置 | 桌面日历配置较少 | 组件有正式 registry，支持启用、禁用、排序和独立配置，并持久化到设置存储 | 待实现 |
| DTD-09 | 多显示器布局记忆 | 未形成每显示器布局 profile | 按显示器组合保存桌面日历位置、尺寸和布局；显示器变化时安全回退，不产生屏外窗口 | 待实现 |
| DTD-10 | 农历、节日、法定假期和外观 | 有校历/学季边界，但非日历格农历节日；主题已有，桌面透明度/背景配置不足 | 日历格显示农历、传统/国际/公式节日和法定假期；支持法定假期导入；桌面背板透明度与设置背景可配置 | 待实现 |

## 范围边界

- 不迁入 `.tmp/DeskToDo` 的 GitHub Gist 同步流程。
- 不改变 Celechron 已验证的认证、请求、Cookie、重定向、缓存、重试、解析和失败边界。
- 课程、考试和上游作业保持只读；可直接编辑的是 CampusOS 自建任务和桌面效率配置。
- 默认数据源仍必须是真实接口或明确的 adapter 边界；天气和节假日不能在 renderer 伪造成功。
- 移动端能力、校园卡和 DingTalk 不因本计划扩大范围。

## 交付顺序

1. DTD-01、DTD-02、DTD-03：先完成桌面操作闭环和生命周期验收。
2. DTD-04、DTD-06、DTD-07、DTD-08：建立可扩展桌面组件 registry。
3. DTD-09、DTD-10：补齐多显示器、日历文化信息和外观配置。
4. DTD-05：接入天气 provider，并以真实上游反馈验收。
