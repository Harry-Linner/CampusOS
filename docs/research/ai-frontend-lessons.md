# AI 制作前端的经验教训与规避清单

**日期:** 2026-08-24
**定位:** 本仓库所有前端实现（含 Phase D 导出分享、Phase E 侧栏子 Tab，以及后续一切 UI 工作）开工前必读的"规避点"清单；与 `AGENTS.md` 的 Implementation integrity 纪律互相印证，属同一套审美/工程红线。
**状态:** 基于对社区"AI 生成前端"经验教训的调研沉淀（来源见文末）。清单为活文档，遇到新的真实翻车案例应补充进来。

> 一句话总纲：**AI 看不见自己生成的东西**——它输出的是 token 流不是像素，所以元素重叠、错位、溢出、间距失衡它自己永远发现不了；它给的第一版永远是训练数据的"平均值"（模板感）。因此：**渲染后看真实截图来评判，而不是只看代码；有意偏离平均值，而不是照搬模板；用可测量的数字验证，而不是凭感觉。**

---

## 一、根本盲区（三条铁律）

1. **AI 无法感知自己产出的视觉结果。** 生成为 token 流，非像素。标题压住图片、按钮溢出视口、间距忽大忽小——它毫无察觉。对策：**渲染 → 截图 → 用"没写过这段代码的眼睛"独立批判**（找子 agent/另开视角挑错，而不是自己给自己的输出找合理性）。
2. **AI 的第一直觉就是平均值。** 第一版 = 训练数据中最常见的组合（居中单列、紫蓝渐变、三等分卡片、glassmorphism…）。"看起来还行"不等于好——**等于又一份模板**。对策：拿第一版当起点，**有意向本产品特定领域偏离**，而不是换个更"潮"的模板。
3. **固定规则本身会成为下一轮平均值。** 12 列栅格、8pt 间距、"等宽字体=数据"这类硬规则被盲执行照样产生碰撞。对策：**规定流程（先看、再量、再改），而不是规定外观**。

---

## 二、规避点清单（按类别）

### A. 无意义的框与装饰（用户点名：不要"随随便便就来一个无意义的框"）

| 症状 | 根因 | 规避 |
|---|---|---|
| 无信息量的装饰性圆角框/卡片套卡片 | 用容器堆层次，而非用内容层次 | 每个框必须有语义：承载一块数据/一组操作；删掉它信息不丢的框就删掉 |
| 抽象 SVG 装饰（波浪/斑点/几何形）塞在背景或区块间 | 用装饰填空白 | 装饰必须与领域语义相关；无关则移除（可用数据可视化/真实截图替代） |
| 装饰性迷你图表（sparkline）只为"显得有数据" | 数据感伪造 | 图表必须传达真实信息；不传达就不加 |
| 网格/噪点/纹理与内容抢注意力 | 效果密度替代设计决策 | 少而有意：层级优先于装饰（hierarchy before decoration） |
| 同款圆角+阴影的"安全盒子"贯穿全页 | 默认组件模板 | 建立 radius/阴影的意图化刻度，按组件类型差异化 |

**自查：** 任意元素移除后信息是否丢失？若不丢 → 它是不必要的框/装饰，删。

### B. 元素重叠与字符碰撞（用户点名：字符重叠）

| 症状 | 根因 | 规避 |
|---|---|---|
| 文本压住图片/按钮/相邻元素 | AI 不知道渲染后的几何关系 | 渲染截图检查；碰撞检测（内容矩形相交 ≥12% 视为嫌疑） |
| 图标/文本基线错位，垂直居中"看着矮" | 几何居中 ≠ 光学居中 | 视觉重心校正：箭头/三角图标右移 1–2px 才"看着居中"；文本按盒子度量居中常偏低，微抬 |
| 图标与文字并排时一方视觉过重 | 等像素尺寸 ≠ 等视觉重量 | 用描边粗细/尺寸/间距匹配两者的视觉重量，形成 lockup |

**自查：** 截图放大检查每个交互元素与文本是否侵入相邻元素；不要只信代码里"应该不会重叠"。

### C. 生造位移与手动对齐（用户点名：生造位移手动对齐）

| 症状 | 根因 | 规避 |
|---|---|---|
| `transform: translate(-50%, ...)`、负 margin、随机 `top/left` 去"对齐" | 用位移硬拼布局，而非文档流/网格产生对齐 | 布局与闭合由正常文档流、Grid/Flex、共享 token 和明确容器自然产生；禁止位移补缝 |
| 逐像素手调 3–7px 让两列"看起来齐" | 没有共享对齐基线 | 靠同一栅格/同一间距 token 对齐；遗留错位应修结构而非打补丁 |
| 边缘锚定的 nowrap 标签（`left:100%` + `translateX(-50%)`）伸出视口 | 居中锚定在边缘的元素必然有一半溢出 | 边缘标签向内锚定（右端 `right:0` 不位移；左端 `left:0` 不位移） |
| 每处都写死像素值（`padding: 13px`、`width: 372px`） | 无 token，逐个魔数 | 间距/圆角/字号/阴影用设计 token；固定像素仅限有组件语义的场合 |

**自查：** 全文搜索 `translate`、负 margin、`position:absolute` 的用法，逐个确认是否有"生造位移对齐"；无语义的魔数一律换 token。

### D. 硬编码像素与魔法数字（延续 C，单列）

- 间距不用 4/8 的倍数而用 13/17/23 → 建立间距刻度（如 4,8,12,16,24,32）并遵守。
- 宽度/高度写死到具体像素且无组件语义 → 用内容尺寸、`min/max`、Grid/Flex 轨道。
- `100vw` 陷阱：包含滚动条宽度（约 15px），纵向滚动页上必然产生横向溢出 → 用 `100%`。
- 多个相同用途处各写各的像素值 → 抽成共享 CSS 变量/token。

### E. 横向溢出（硬门禁，无例外）

> **未跑过 `scrollWidth` 检查前，禁止宣称页面"完成/正常"。** 这不是建议，是门禁。

- **为什么是头号问题：** 开发视口（1440px）太宽，溢出只在窗口窄于某元素时才出现（约 720–1200px 区间最容易中招），开发时完全看不见。
- **最常见成因：**
  - 头部/导航/工具栏 flex 单行 `nowrap`，加了个 tab/按钮/徽章就撑破（每次给横向行加元素，**上一次的溢出检查即失效，必须重测**）
  - `position:absolute` + `nowrap` 锚在边缘
  - `100vw`
  - flex/grid 子项没有 `min-width:0`，长内容拒绝收缩撑爆轨道
  - 超长不可断字符串（URL/哈希/token）→ `overflow-wrap:anywhere`
  - 固定像素宽度大于视口、大负 margin、超大绝对定位元素
- **默认防御（先做，让门禁天然通过）：** 头部行 `flex-wrap: wrap`（绝不 `nowrap`）；`body { overflow-x: clip }` 兜底（clip 而非 hidden，不破坏 sticky）。
- **检查命令：** `document.documentElement.scrollWidth - document.documentElement.clientWidth` 必须为 0，在开发宽度 + 窄屏（≤1024px）+ 手机宽度（~390px）各测一次；>0 时逐个元素定位溢出源。兜底 ≠ 修复，找到根因改掉。

### F. 间距与节奏体系

- 间距一致性：同容器子项间 gap 的变异系数是"节奏"的量化信号；AI 输出常见"接近一致但有随机偏差"。
- 空白（empty space）是节奏工具：有意留白制造节奏与焦点；AI 倾向"用内容填满空白"。判定表（有意极简 vs AI 糊弄）：间距一致 vs 随机偏差、配色受限自品牌 vs 跟风流行色、文案高信息密度 vs 泛泛而谈、布局服务内容层级 vs 套模板结构。

### G. 视觉平衡（可测量，不靠感觉）

- 平衡 = 视觉重量的质心，可计算：`质心 = Σ(重量×位置)/Σ重量`，目标 ≈ x=0.50、y≈0.46（略高于几何中心，否则"看着下沉"）。
- 重量 ≠ 面积：实心标题重、浅灰小字轻，按墨迹密度加权。
- 修正手段按成本排序：加重对侧元素 → 增大对侧 → 把重元素拉向中心（缩短力臂）→ 缩小它。
- **验证：** 截图后按真实像素计算墨迹质心，与光学中心比较（|dx|<0.03、|dy|<0.04 量级）；不要问 VLM"居中了吗"——它会给幻觉答案。注：刻意的不对称是创作工具，别为了"平衡分"把设计改平庸（见第五节"信号 vs 门禁"）。

### H. 效果滥用（一眼 AI 的配方）

| 配方 | 规避 |
|---|---|
| 紫蓝渐变、粉橙、青绿渐变当主背景 | 渐变只做点缀，且从品牌色推导 |
| 霓虹暗色：暗底 + 青/紫高亮 + 发光 | 无产品理由不用 glow |
| glassmorphism 滥用：全屏毛玻璃卡片 | 毛玻璃只用于有层次语义的浮层 |
| 全站卡片同款大圆角（≥16px 占比 >60%） | 建圆角刻度（2/4/8/16…）按组件类型差异化 |
| 50%+ 容器都带 box-shadow、多处 backdrop blur | 建立 2–3 级阴影体系；大部分元素保持扁平 |
| 渐变文字标题"求冲击"、无层次逻辑的彩色描边 | 层级优先，效果从简 |

### I. 模板感与平均值（结构性）

- 标准 AI 页面结构（Hero 居中 → 三等分特性卡 → 评价 → 三档定价 → CTA → 四栏页脚）→ 按本产品的真实用户任务重排区块顺序。
- 三等分卡片（icon+h3+p 完全同构）→ 变数量、加差异化、突出主卡。
- 千篇一律的"图标徽章+标题"特性块 → 用真实截图/交互元素。
- 判定自检：把内容换成另一家公司的，几乎无感知 → 你出货的是平均值。

### J. 文案空洞（顺带，前端常有）

- 泛泛 CTA（"立即开始""了解更多"）→ 写具体动作与结果。
- 词汇密度过高（无缝/强大/革新/赋能…每百字 >2%）→ 换成可量化事实。
- 占位残留（Lorem、全等长段落）→ 用真实文案。

## 三、验证流程（每轮 UI 交付前的固定动作）

1. **渲染**：真实渲染页面（本地 serve + 截图），多宽度（桌面 / ≤1024 / ~390）。
2. **独立批判**：用"没写这段代码"的视角（子 agent 或换个 prompt）专门找错：碰撞、边缘切线、参差对齐、失衡、窄屏断裂、无焦点。
3. **硬门禁**：`scrollWidth - clientWidth == 0`（窄屏必测）；对比度 WCAG ≥4.5（大字 ≥3）；交互目标 ≥44×44。
4. **像素校验**：平衡/对齐等"感觉类"判断用数字（墨迹质心、对齐簇、间距变异系数），并**看标注后的截图**（数字只告诉你看哪里，最终用眼睛裁决）。
5. **迭代**：改 → 重渲染 → 重判 → 直到门禁全过且独立评判无"事故级"问题。

## 四、门禁 vs 信号（验收时不要混淆）

- **门禁 = 正确性**：横向溢出、对比度、点击目标、碰撞。不通过就是缺陷，可安全拦截。
- **信号 = 惯例**：对称平衡、网格对齐、节奏均一。它衡量的是"贴不贴近对称/网格的平均审美"——**把信号分拉满会做出更无聊的设计**。信号只用来抓"你没打算的意外"（7px 意外漂移、幻影滚动条），**不许用信号去纠正有意的设计选择**（故意的重叠、不对称 hero）。指标与好设计冲突时，好设计赢。

## 五、与本仓库现有纪律的衔接

`AGENTS.md` Implementation integrity 已有同向约束，本清单是其外部证据与操作化补充：

- 禁止 `transform: translate(...)`、随意负边距、任意 `top/left` 偏移拼缝对齐 → 对应本清单 **C 节**。
- 固定像素仅限有组件/设计 token 语义 → 对应 **C/D 节**。
- 布局由文档流/Grid/Flex/共享 token 自然产生 → 对应 **A/C/F 节**。
- 交付前"与风险相称的视觉与行为验证" → 对应 **第三节验证流程**。
- 所有 UI 相关实现（Phase D/E 及以后）**必须先渲染截图再宣称完成**。
