## One-liner

**纯粹的"外部信息"早报插件**：每天一份全中文的个人资讯日报，把我关注的外部领域（技术/AI、学术、通识、文学/网络报刊）的最新动态聚合、去重、AI 摘要成板块化日报，并固定留出"发现板块"打破信息茧房；兴趣画像由 AI 从**外部个人数据库**（Obsidian 等本地 Markdown）自动提炼，作为**抓取权重自动调整的依据**；CampusOS 是看板与中间站 —— 校园信息由**独立插件**承担，日程展示与提醒继续由 Schedule 插件负责。

---

## Problem statement

日常生活重复、信息获取碎片化：外部消息散落在各个站点（RSS、公众号、论坛、arXiv），且人一旦依赖已有信息源就困在**信息茧房**里，消息越来越闭塞。现成工具三类割裂 —— 新闻摘要（ChatGPT Pulse/Gemini）不知道你是谁；日程工具不知道世界发生了什么；笔记 AI 不抓外部实时信息。用户需要的是一份"**多源聚合 + 个人画像驱动 + 刻意破茧**"的晨间日报，目前没有现成产品覆盖。

**明确边界：** ①早报**不含校园信息**（校园信息由独立插件承担，另立项）；②早报**不做**今日安排、时间块建议、日程写入（归 Schedule 插件）。

## Target user

**本人（Harry，开发者）** → 以官方插件形态逐步面向 ZJU 学生。

**Persona:** 每天桌边 ≥3 小时，写 Obsidian 日记，关注技术/AI、学术、通识与文学等多领域；每天愿意花 **30min–1h** 读早报；痛点是外部信息零散化与信息茧房；希望早报"自动跟上我的兴趣流变"，并且**有选择地**把有价值的早报沉淀进个人知识库。

---

## Jobs-to-be-done（top 4）

1. 晨间拿到**多源聚合的外部领域资讯摘要**（全中文、去重、按画像权重配额、可点击原文）——替代人工轮询 N 个站点。
2. 让"关注领域"**自动跟上我的流变**（AI 每周从个人库提炼画像 → 我确认 → 抓取权重随之调整 → 早报内容变化）。
3. **破茧**：发现画像外的新领域与新信息源（每日少量"发现"条目 + 每周新源推荐），对抗信息茧房。
4. **有选择地归档**：把有价值的早报条目/整期归档进个人数据库，丰富自己的知识库。

**反 JTBD（不做）:** 社交、即时聊天、无限新闻流、日程管理、时间块建议、校园信息 —— 早报是减熵工具，不是另一个信息源，也不是日历。

## Success metrics

### North Star
**早报周查看率** —— 一周内打开早报 ≥5 天的比例（个人目标 ≥70%；官方插件 WAU 内 ≥40%）。

### Leading（影响现在）
- 早报生成成功率 ≥ 95%
- 画像提炼每周确认率 ≥ 80%
- 资讯抓取成功率 ≥ 90%（缓存降级除外）
- 发现板块周点击 ≥ 1 次（破茧在起作用）

### Lagging（看结果）
- 归档条目数/周（用户主动沉淀的量）
- 新信息源订阅数/月
- 资讯点击率（摘要 → 原文）

### Counter-metrics（不能变差）
- 早报生成延迟 > 30s 的比例 < 5%
- 因打扰关闭早报通知的比例 < 10%
- CampusOS 启动时间、后台内存不因早报模块劣化（沿用现有 NFR）

## Solution shape

三层架构（详见 [research](research.md) 第 5、11 节）：

```
捕获层（外部个人库）         画像层（CampusOS SQLite）        生成/展示层（CampusOS）
Obsidian 等本地 Markdown  →  结构化领域+权重+目标，          AI 合成板块化日报
（只读，仅作画像依据）        每周提炼+确认+流变检测           → 详情页 + 通知
                             手动兜底可编辑
```

- **个人数据库的角色（用户明确）：** 只提供**画像依据**，让 AI 自动调整抓取信息权重 —— 不是信息源本体，不做展示；归档是用户主动的可选动作。
- **AI library 调研结论：** 不引入任何外部知识库平台（RAG 平台 / 记忆框架 / MCP server）。MVP 直接读文件夹；Phase 1+ 可选**本地语义检索**（embedding + 向量）增强"找画像依据"能力（详见 research 11.7）。
- **模块形态：** 官方插件，左侧栏一个入口；模块内二级标签页：`日报 / 画像 / 设置`（插件允许内部 tab，参照 Academic 先例）。
- **资讯：** Core connector 抓取（RSS + 预设公开源 + 白名单网页三轨），去重指纹、缓存、降级（参考天气 provider 模式）；配额由 **AI 按画像权重分配**。
- **校园信息：** 由**独立插件**承担（另立项），早报不消费校园源；未来如需协作，以 capability 订阅校园插件的通知能力（可选，不阻塞）。
- **破茧：** 日报固定预留画像外配额（如 1–2 条"发现"）；每周新源推荐；每周领域分布图（茧房显性化）。
- **归档：** 用户对单条/整期**可选**归档，写回个人库（Markdown 约定模板），有筛选地沉淀。
- **AI 与隐私：** 复用 `aiProviderAdapters` + safeStorage key，效率优先直接转发提炼内容；**一次性 onboarding consent + 设置页可整体关闭**（实现时形成独立 ADR，记录与 ADR-0004 的差异）。
- **提醒：** 开机自动生成 + 可手动刷新 + 桌面通知（复用通知中心）。

## Scope and non-goals

### In scope
- 早报官方插件（manifest + catalog 注册；`日报 / 画像 / 设置` 二级 tab）
- personal-DB connector（读本地 Markdown 文件夹：Daily Notes + `interests/` + frontmatter `tags`/`goals`；仅画像依据）
- 画像服务（提炼、确认、存储、流变检测、手动兜底、权重输出）
- 资讯 connector（RSS + 预设公开源 + 白名单网页；去重、缓存、降级）
- 早报合成服务（AI 板块化摘要 + 配额分配；复用 aiProviderAdapters）
- 破茧发现板块 + 每周新源推荐 + 领域分布图
- 展示：板块化详情页（全中文、摘要 + 原文外开 `shell.openExternal`）
- 归档：用户可选，写回个人库
- 提醒：开机自动生成 + 桌面通知（复用通知中心）
- consent 记录与 ADR（一次性 onboarding + 设置页整体开关）

### Non-goals（明确不做）
- **校园信息聚合** —— 独立插件另立项；早报不含校园源
- **今日安排 / 时间块建议 / 日程写入** —— 归 Schedule 插件
- **应用内嵌浏览器** —— v2 可选独立阅读窗口，不进 MVP
- **移动端推送** —— post-MVP Android Companion
- **社交/分享/协作**
- **云同步** —— 延续纯本地
- **本地 LLM 适配器（Ollama）** —— 用户已选效率优先走云端
- **第三方插件开放资讯抓取** —— 抓取保持 Core connector 边界
- **引入 RAG 知识库平台 / AI 记忆框架 / MCP server 依赖** —— 调研结论：不需要（research 11.7）

## Assumptions

- 用户会持续写日记（≥3 次/周）`[load-bearing]`
- 愿意建立并遵守 vault 约定（Daily Notes + `interests/` + frontmatter）`[load-bearing]`
- 云端 LLM 转发可接受（一次性 consent + 设置页可关，用户已决策）
- 白名单公开源可行；开放网页抓取需逐源合规评估
- 30min–1h 的每日阅读时长会持续（板块可多、可展开）
- 归档目标 = 个人库的 Markdown 约定模板（格式待定）
- 个人数据库仅作画像依据，不承担展示/信息源职责（用户明确）

## Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| 早报被习惯性忽略（30min–1h 太长反而弃读） | 中 | 高 | 板块可折叠；默认只展开 2–3 个高频板块；固定生成时间 |
| 日记→云端 LLM 的 consent 与 ADR-0004 冲突 | 确定 | 中 | 实现时独立 ADR：一次性 onboarding consent + 设置页可见可关 |
| 信息茧房破壁失败（发现板块没人点） | 中 | 中 | 配额/取样算法可调；领域分布图让问题可见 |
| 画像提炼漂移/噪声 | 中 | 中 | 每周确认制，确认后才生效 |
| 抓取合规（版权/ToS/反爬） | 中 | 中 | 白名单源；只摘要不全文转载；逐源评估 |
| 用户不写日记 → 画像枯竭 | 中 | 中 | 手动维护兜底；无画像时早报按默认领域运行 |
| 归档格式漂移（个人库约定变化） | 低 | 中 | 归档模板集中定义、版本化 |
| 校园/早报边界后续反复 | 低 | 中 | 两插件以 capability 协作解耦，边界改动不影响各自核心 |

## Compliance notes

- 本模块会向云端 LLM 发送用户日记/笔记提炼内容（用户已决策：效率优先）。与现有 AI 助手"仅发送用户显式提交的消息"（ADR-0004）不同，**实现前必须**形成独立的 consent 设计与 ADR 记录：一次性 onboarding 确认 + 设置页可整体关闭模块。
- 外部资讯抓取仅限白名单公开源，只做摘要不做全文转载。
- 校园信息抓取属独立插件范围，不在本模块合规面内。
